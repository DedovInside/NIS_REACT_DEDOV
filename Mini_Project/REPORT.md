**Автор:** Дедов Иван Андреевич
**Дата:** Март 2026  
**Тема:** Карточная игра-стратегия на Vue 3 + TypeScript + Pinia с интеграцией Telegram Mini Apps

---

## Суть приложения

SpellJack - браузерная карточная игра, реализованная как Telegram Mini App. В основе лежат правила блэкджека, существенно расширенные авторскими механиками: динамическая цель (от 21 до 100 очков), система мультипликаторов мастей и 21 уникальная специальная карта с разными типами активации.

Суть игрового цикла: перед партией игрок формирует колоду из доступных карт (в Редакторе колоды) и выбирает до трёх специальных карт. В ходе игры он берёт карты, накапливая очки с учётом мастевых коэффициентов, и активирует спецкарты - как вручную (например, «Двойной удар», «Критический выбор»), так и пассивно (например, «Щит перегруза», «Огненный туз»). За победы игрок получает монеты и покупает новые специальные карты в магазине, постепенно расширяя стратегические возможности.

## Технологии

### Vue 3 (Composition API + `<script setup>`)

**Общее описание.** Vue 3 - прогрессивный JavaScript-фреймворк для построения пользовательских интерфейсов. Ключевое нововведение третьей версии - Composition API, который позволяет организовывать логику компонента не по типу опции (`data`, `methods`, `computed`), а по смысловой принадлежности. Синтаксис `<script setup>` - синтаксический сахар поверх Composition API, устраняющий лишний бойлерплейт.

**Зачем использовался.** Реактивная система Vue 3 (`ref`, `reactive`, `computed`, `watch`) хорошо подходит для игровой логики с множеством взаимосвязанных состояний. Ключевым архитектурным решением стало разбиение логики на специализированные composables по принципу единственной ответственности: `useCardScoring` - подсчёт очков (коэффициенты мастей, хронометр, королевский указ), `useDeckBuilder` - создание и перемешивание колод, `useSpecialCardActions` - обработка всех 21 специальных карт, `useGameLoop` - основной игровой цикл (старт, Hit, Stand, ход дилера). Компонент `MainGame.vue` превратился в тонкий оркестратор (~100 строк скрипта): подключает composables, связывает их между собой и рендерит шаблон. Директивы Vue (`v-if`, `v-for`, `v-model`) и система `emit`/`props` покрыли все сценарии взаимодействия между компонентами.

**Сравнение с React (TypeScript).** В React аналогом Composition API являются **Custom Hooks** (`useXxx`), и структура composables в Vue намеренно похожа на эту концепцию. Однако есть принципиальные отличия:

- **Шаблоны vs JSX.** Vue использует HTML-подобный шаблонный синтаксис (`<template>`), React - JSX (JavaScript + разметка в одном выражении). Шаблоны Vue читаются как обычный HTML и более привычны для разработчиков с опытом в вёрстке; JSX даёт больше свободы за счёт полной мощи JavaScript.
- **Реактивность.** Vue предоставляет встроенную реактивную систему - `ref()` и `reactive()` отслеживают зависимости автоматически. В React для локального состояния используется `useState`, для сложных сценариев - `useReducer` или внешние библиотеки. Vue-реактивность прозрачнее: нет необходимости явно перечислять зависимости в массиве `deps`, как в `useEffect`.
- **`v-model`.** Двустороннее связывание `v-model` работает из коробки. В React аналог - управляемые компоненты с парой `value`/`onChange`, что требует чуть больше кода.
- **Производительность.** Vue 3 использует компилируемые шаблоны, что позволяет делать более точечные обновления DOM. React использует виртуальный DOM с диффингом; разница в производительности незначительна для большинства задач.

Другие альтернативы: Angular - полноценный фреймворк с DI-контейнером, избыточен для одностраничного приложения среднего размера. Svelte компилирует компоненты в нативный JS, даёт минимальный бандл, но имеет меньшую экосистему и меньше готовых решений.

### TypeScript

**Общее описание.** TypeScript - типизированное надмножество JavaScript, разрабатываемое Microsoft. Добавляет статическую типизацию, интерфейсы, дженерики и расширенный инструментарий IDE без изменения рантайма - TypeScript компилируется в чистый JavaScript.

**Зачем использовался.** Игровая логика SpellJack включает сложные структуры данных: карты двух видов (`Card`, `SpecialCard`), набор из 20+ активных эффектов (`ActiveEffects`), мультипликаторы мастей (`SuitMultipliers`), результаты предсказания карты судьбы (`DestinyPreview`). Без типизации поддерживать этот код затруднительно. TypeScript позволил явно описать все интерфейсы в `types/index.ts`, получить автодополнение в IDE и поймать ряд ошибок ещё на этапе компиляции - в частности, обращения к потенциально `undefined`-полям, несоответствие типов в аргументах composable-функций. Отдельно выделен тип `ActiveEffects` с точными типами для каждого из 21 эффекта - это исключило неочевидные баги. Финальная проверка: `npx vue-tsc --noEmit` - ни одной ошибки.

**Сравнение с React TS.** В проектах на React TypeScript используется ровно так же: типизируются `props` через интерфейсы, хуки возвращают типизированные значения. Принципиальное различие - в способе типизации компонентов. Vue использует `defineProps<T>()` и `defineEmits<T>()` для типизации входных данных компонента, React - интерфейс `Props` как аргумент функции-компонента. Оба подхода эквивалентны по строгости; специфика Vue лишь в том, что props и emits объявляются компиляторными макросами, а не обычными переменными. Альтернатива TypeScript - JSDoc-аннотации (частичное автодополнение без компиляции), Flow (практически вышел из использования). TypeScript - де-факто стандарт для современных Vue- и React-проектов.

### Pinia

**Общее описание.** Pinia - официальный менеджер состояния для Vue 3, рекомендованный командой Vue как замена Vuex. Построен поверх реактивной системы Vue, полностью поддерживает TypeScript и Vue DevTools, не требует мутаций и имеет минималистичное API: `state`, `getters`, `actions`.

**Зачем использовался.** Весь игровой стейт (монеты, колода, коллекция карт, активные эффекты, мультипликаторы мастей, магазин) должен быть глобальным и реактивным - доступным одновременно из `MainGame`, `Shop`, `DeckEditor`. Стор `game.ts` содержит все игровые данные, более 20 action-методов (`buyCard`, `applyCardEffect`, `resetGameEffects`, `generateSuitMultipliers`, `checkPassiveEffects` и др.) и геттер `manualActivationCards`. Благодаря TypeScript весь стор полностью типизирован.

**Сравнение с аналогами в React.** В React-проектах для глобального состояния используют **Redux Toolkit**, **Zustand** или **MobX**. Pinia концептуально ближе всего к Zustand: минимальный бойлерплейт, состояние объявляется в одном объекте, нет отдельного слоя мутаций. Redux Toolkit мощнее (middleware, dev-tools, code splitting), но многословнее. MobX использует реактивные наблюдаемые и декораторы - мощный инструмент, но с более крутой кривой обучения и меньшей органичностью в Vue-экосистеме. Vuex (предшественник Pinia) требовал явных `mutations` и был намеренно более строгим - Pinia отказалась от этого ограничения, сохранив возможность отслеживать изменения через DevTools.

### Vue Router

**Общее описание.** Vue Router - официальная библиотека маршрутизации для Vue. Поддерживает history-режим, ленивую загрузку компонентов, вложенные маршруты и навигационные хуки (`beforeEach`, `afterEach`).

**Зачем использовался.** Приложение имеет три отдельных экрана: основная игра (`/`), магазин (`/shop`) и редактор колоды (`/deck-editor`). Vue Router организует переходы между ними без перезагрузки страницы. Все три маршрута используют динамический импорт (`() => import(...)`) - code splitting из коробки, каждый экран загружается только при первом переходе. Файл `vercel.json` настроен на перенаправление всех запросов на `index.html`, что необходимо для SPA в history-режиме.

**Сравнение с React Router.** `react-router-dom` - концептуально похожее решение для React: те же history-режим, lazy-loading через `React.lazy()`, навигационные хуки (`useNavigate`, `useParams`). Принципиальное отличие - синтаксис объявления маршрутов. Vue Router использует конфигурационный массив объектов (`routes: [{ path, component }]`), React Router v6 - JSX-декларативные `<Routes>/<Route>` или объектный формат через `createBrowserRouter`. Оба подхода функционально эквивалентны; разница в стиле кода, диктуемом самим фреймворком.

### Vite

**Общее описание.** Vite - современный инструмент сборки, использующий нативные ES-модули браузера в dev-режиме (избегая предварительного бандлинга) и Rollup для production-сборки. Обеспечивает мгновенный старт dev-сервера и быстрый HMR (Hot Module Replacement).

**Зачем использовался.** Vite - стандартный инструмент сборки для Vue 3. Он создаёт scaffolding через `create-vue`, поддерживает TypeScript и `.vue`-файлы из коробки через плагин `@vitejs/plugin-vue`. Скорость холодного старта и обновлений при разработке значительно выше, чем у webpack-based решений. В `vite.config.ts` настроен путевой алиас `@` для удобных импортов.

**Сравнение с аналогами.** Webpack - более зрелый инструмент с обширной экосистемой плагинов, де-факто стандарт в React-проектах через Create React App и Next.js, но медленный на старте. Parcel прост в настройке, но менее гибкий. Для Vue 3 и React Vite является официально рекомендованным выбором.

### Telegram Web App SDK

**Общее описание.** Telegram Mini Apps - платформа для встроенных веб-приложений внутри Telegram. SDK предоставляет JavaScript API: данные пользователя, тактильная обратная связь (HapticFeedback), цветовая схема клиента, управление MainButton.

**Зачем использовался.** Приложение разрабатывалось для платформы Telegram Mini Apps. Composable `useTelegram.ts` инкапсулирует всю логику интеграции: инициализацию SDK (`ready()`, `expand()`), получение данных пользователя из `initDataUnsafe`, вибрацию при игровых событиях (победа → `success`, проигрыш → `error`, подсказка → `warning`). Это создаёт нативный пользовательский опыт внутри мессенджера.

**Сравнение с аналогами.** VK Mini Apps (VK Bridge) - аналогичная по концепции платформа: тоже предоставляет JS-мост между веб-приложением и нативным клиентом, тоже поддерживает данные пользователя и вибрацию. Принципиальные отличия: VK Mini Apps требует прохождения модерации для публикации, Telegram Mini Apps доступны сразу. PWA (Progressive Web App) - более универсальное решение (любой браузер), но без глубокой интеграции с мессенджером и без доступа к данным пользователя мессенджера.

### Vercel

**Общее описание.** Vercel - облачная платформа для деплоя фронтенд-приложений. Поддерживает автоматический деплой при пуше в GitHub, глобальный CDN, HTTPS из коробки.

**Зачем использовался.** Telegram Mini Apps требует HTTPS-хостинг с постоянным URL. Vercel обеспечивает это бесплатно. Настройка минимальна: подключить репозиторий, Vite-проект детектируется автоматически. Файл `vercel.json` с `rewrites` решает проблему 404 при прямом переходе на SPA-маршруты - все запросы перенаправляются на `index.html`.

**Сравнение с аналогами.** Netlify - практически идентичная альтернатива с аналогичными возможностями и таким же бесплатным тарифом. GitHub Pages не поддерживает серверные rewrites для SPA-роутинга без дополнительных хаков. Firebase Hosting мощнее (интеграция с Firebase Functions), но сложнее в настройке для простого статического деплоя.

## Заключение

В ходе работы над проектом была разработана карточная игра-стратегия SpellJack на стеке Vue 3 + TypeScript + Pinia + Telegram Mini Apps. Это позволило глубоко изучить Vue 3 в сравнении с React - двумя главными современными инструментами фронтенд-разработки.

**Впечатления от Vue 3.** Composition API оказался очень удобным для компонентов с комплексной логикой - вся связанная функциональность размещается рядом, а не разбита по опциям (как это было бы в Options API или в React-компонентах). Директивы Vue (`v-if`, `v-for`, `v-model`) читаются интуитивно, особенно для HTML-разметки. В сравнении с React/JSX подход с отдельным `<template>` более явно разделяет логику и представление, что упрощает восприятие структуры компонента.

**Впечатления от Pinia.** Pinia значительно проще, чем Redux: нет `actions`/`reducers`/`dispatch`, нет необходимости описывать `ActionTypes`. По сравнению с MobX (который часто используется в React-проектах) - нет декораторов и `makeObservable`. При этом функциональности для данного проекта (сложный игровой стейт с 20+ эффектами) Pinia хватило полностью. Интеграция с Vue DevTools позволяет отслеживать каждое изменение стора в реальном времени - это существенно ускорило отладку.

**Впечатления от TypeScript.** Типизация игровых структур заняла дополнительное время на старте, но окупилась: IDE подсказывала поля объектов, а несколько потенциальных ошибок (обращение к `undefined` в цепочках, несоответствие типов при передаче `Ref` в composable) были пойманы до запуска. Разница между `Ref<Card[]>` и `ReturnType<typeof ref<Card[]>>` - пример того, где строгая типизация сразу выявила неочевидную ошибку.

**Рефлексия.** Наиболее трудоёмкой частью оказался рефакторинг `MainGame.vue` - изначально монолитного компонента. Вся логика была разнесена по четырём composables (`useGameLoop`, `useSpecialCardActions`, `useCardScoring`, `useDeckBuilder`), а сам `MainGame.vue` стал тонким оркестратором: подключает composables, связывает их и рендерит шаблон. Это - прямой аналог паттерна Custom Hooks + Container Component в React, только реализованный средствами Vue. Итог: читаемость, тестируемость и архитектурная оценка проекта существенно улучшились. Главный вывод: Vue 3 и React решают одни и те же задачи разными, но во многом симметричными средствами; выбор между ними в большей степени определяется предпочтениями команды и экосистемой проекта, чем принципиальными техническими ограничениями.
